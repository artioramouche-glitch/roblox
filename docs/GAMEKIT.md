## GameKit tools

- **roblox_start_here** — START HERE before anything else. Checks the Studio connection, shows what is already in the game, and gives the step-by-step plan to build a complete game with this MCP (templates, systems, testing).
- **roblox_guide** — Read a short guide. Topics: workflow, design, luau, client-server, data, ui, building, testing, errors, publishing, performance, gamekit-api, catalog, or any system/template id (e.g. "shop", "obby"). Read "workflow" first, "errors" when something breaks.
- **gamekit_catalog** — List everything that can be installed without code: complete game templates, plug-and-play systems, world pieces and lighting presets.
- **create_game** — Build a COMPLETE playable game in one call: scripts (server+client), config, world, UI and lighting. Templates: obby (Obby), tycoon (Tycoon), simulator (Simulator), arena (Fighting), survival (Survival), horror_escape (Horror). By default removes previous GameKit content first (Ctrl+Z in Studio undoes everything). Then run test_game.
- **add_system** — Install one ready-made, tested game system (plus what it needs). Systems: hud, checkpoints, hazards, movers, collectibles, rounds, combat, enemies, shop, daily, leaderboard, movement, atmosphere, admin, monetization, tycoon, simulator, objectives. Pass "config" to change its settings (existing settings are kept otherwise). Read roblox_guide <system> for its options.
- **build_world** — Build gameplay-ready geometry in Workspace/GameKit (anchored, tagged for the systems). Worlds: obby_course, lobby, arena, maze, tycoon_plots, simulator_world, decor_scatter. Pieces: platform, spawn, checkpoint, finish_line, kill_brick, lava_floor, damage_part, heal_pad, jump_pad, speed_pad, boost_pad, moving_platform, spinner, disappearing_platform, falling_platform, conveyor, coin, shop_stand, leaderboard, enemy_spawner, sell_pad, zone_gate, teleporter, teleport_target, key, tree, rock, lamp, crate. Same name = replaced. Positions are [x, y, z] in studs, y is up.
- **build_ui** — Create a screen UI from JSON (no Luau): frames, labels, buttons, images, bars with responsive sizes and nice defaults. Behaviour without code: bind "stat:Coins" (live text), bar "stat:Power/stat:Capacity", showIf, action "toggle:WindowName" | "open:X" | "close:X" | "remote:Event". See roblox_guide ui.
- **set_environment** — Change the mood: lighting preset (day, sunset, night, horror, fantasy, neon, winter, desert, space, underwater), time of day, terrain (none, clear, flat, hills, island, water), remove the default Baseplate.
- **write_script** — The SAFE way to create or replace a script. Checks the Luau with the real compiler and a beginner-mistake linter BEFORE writing; refuses broken code and explains how to fix it. kind: server (Script), client (LocalScript) or module (ModuleScript); default from the location.
- **check_luau** — Check Luau code WITHOUT writing it: real compiler syntax check + beginner-mistake linter (client/server confusion, infinite loops, deprecated APIs, trusting the client...). Works even when Studio is closed.
- **check_game** — Audit the whole place without playing: syntax errors in every script, beginner mistakes, scripts that can never run where they are, missing spawn, loose unanchored parts, GameKit pieces without their system. Returns problems with fixes.
- **test_game** — Automatic playtest: starts Play, plays through the game (checkpoints, coins, kill parts), records server AND client errors with script/line and plain-English fixes, then stops by itself and cleans up. Run it after every change until it says PASS.

## Systems (add_system)
- **core** [core] -- Saving/loading player data with DataStores, leaderstats, remotes (Net), shared helpers (Util), UI kit (UIKit) and the no-code UI binder.
- **hud** [ui] -- Stats panel with +N pop-ups, status/timer bar, toast notifications, and the left column of HUD buttons used by other systems. (needs: core)
- **checkpoints** [gameplay] -- Saved stage progress, respawn on the last checkpoint, finish line rewards. (needs: core, hud)
- **hazards** [gameplay] -- Kill bricks, damage parts and heal pads. (needs: core)
- **movers** [gameplay] -- Moving platforms, spinners, disappearing and falling platforms, conveyors, teleporters, jump/speed/boost pads. (needs: core)
- **collectibles** [economy] -- Spinning coins/orbs that give a stat and respawn. (needs: core, hud)
- **rounds** [gameplay] -- Intermission -> round -> winners loop with timer, map rotation, rewards. (needs: core, hud)
- **combat** [gameplay] -- Ready sword tool, server-side hit detection with anti-cheat range check, kill rewards. (needs: core, hud)
- **enemies** [gameplay] -- Chasing NPCs with pathfinding, attacks, rewards; optional wave survival mode. (needs: core, hud)
- **shop** [economy] -- Server-validated shop window: speed/jump boosts, tools, trails, multipliers, pets, repeatable upgrades. (needs: core, hud)
- **daily** [economy] -- Claim a reward every day with a growing streak (great for retention). (needs: core, hud)
- **leaderboard** [ui] -- In-world board with the all-time top 10 of any stat across all servers. (needs: core)
- **movement** [gameplay] -- Shift to sprint (button on mobile) and a double jump. (needs: core)
- **atmosphere** [world] -- Day/night cycle, background music playlist, flickering lights. (needs: core)
- **admin** [gameplay] -- Chat commands for the owner: /give, /set, /reset, /kick, /tp, /bring, /speed, /heal. (needs: core, hud)
- **monetization** [economy] -- Developer products and game passes with safe receipt handling (no double grants). (needs: core, hud)
- **tycoon** [genre] -- Claimable plots, droppers -> conveyor -> collector, purchase buttons in order, saved progress. (needs: core, hud, movers)
- **simulator** [genre] -- Train -> backpack -> sell -> upgrades -> zones -> rebirth loop. (needs: core, hud, collectibles)
- **objectives** [genre] -- Find keys, open the exit door, escape; the run resets automatically. (needs: core, hud)

## Lighting presets (set_environment)
- **day**: Bright, friendly daylight. Good default for obbies, simulators and tycoons.
- **sunset**: Warm orange evening light, cinematic.
- **night**: Calm starry night with blue moonlight.
- **horror**: Very dark, dense fog, desaturated. For horror/escape games (add FlickerLight lamps).
- **fantasy**: Dreamy purple-pink magical light with strong glow.
- **neon**: Cyberpunk night: purple haze and heavy glow on Neon parts.
- **winter**: Cold bright snowy day.
- **desert**: Hot hazy desert sun.
- **space**: Black sky full of stars, no atmosphere.
- **underwater**: Blue-green murky underwater look.

## Systems in detail
### System: Core (always installed) (core)

Saving/loading player data with DataStores, leaderstats, remotes (Net), shared helpers (Util), UI kit (UIKit) and the no-code UI binder.

Requires: nothing
Scripts: shared/Util.luau, shared/Net.luau, shared/UIKit.luau, core/PlayerData.luau, core/Core.server.luau, core/UIBinder.client.luau

#### Config.PlayerData
```json
{
  "DataStoreName": "GameKit_PlayerData_v1",
  "AutoSaveSeconds": 90,
  "Stats": [],
  "KickOnLoadFailure": true
}
```
- DataStoreName: Change this name to start everyone from zero (old saves are ignored).
- AutoSaveSeconds: How often everyone is saved (also saved on leave and shutdown).
- Stats: Extra stats: { { Name = "Gems", Default = 0, Leaderstat = true } }. Systems add their own stats automatically.
- KickOnLoadFailure: Kick players whose data failed to load (protects their save). Never kicks in Studio.

#### Config.Core
```json
{
  "WelcomeMessage": "Welcome!",
  "StartingStatus": ""
}
```
- WelcomeMessage: Toast shown to each player after joining ("" to disable).
- StartingStatus: Text in the top status bar at start ("" hides it).

#### Config.Theme
```json
{
  "Background": "#16161F",
  "Panel": "#23232F",
  "Accent": "#FFC940",
  "Text": "#FFFFFF",
  "SubText": "#B8B8C8",
  "Success": "#4CD964",
  "Error": "#FF5A5A",
  "Reward": "#FFC940",
  "Info": "#5AB4FF",
  "Font": "FredokaOne",
  "Corner": 12
}
```
- Accent: Main button color of every GameKit window.
- Font: Any Enum.Font name, e.g. "GothamBold", "Arcade", "Cartoon".

#### How to use
Server scripts: local PlayerData = require(game.ServerScriptService.GameKit.PlayerData) then PlayerData.defineStat({Name="Coins", Default=0, Leaderstat=true}), PlayerData.reward(player, "Coins", 10), PlayerData.spend(player, "Coins", 50). Client scripts read any stat with player:GetAttribute("Coins"). Remotes: Net.on("Name", fn) on the server, Net.send("Name", ...) on the client.
### System: HUD (hud)

Stats panel with +N pop-ups, status/timer bar, toast notifications, and the left column of HUD buttons used by other systems.

Requires: core
Scripts: systems/hud/HUD.client.luau

#### Config.Hud
```json
{
  "ShowLeaderstats": true,
  "ExtraStats": [],
  "HiddenStats": [],
  "ShowStatus": true,
  "Icons": {
    "Coins": "💰",
    "Cash": "💵",
    "Gems": "💎",
    "Wins": "🏆",
    "Stage": "🚩",
    "Kills": "⚔️",
    "Level": "⭐",
    "Power": "⚡",
    "Rebirths": "🔁",
    "Keys": "🔑",
    "Wave": "🌊"
  }
}
```
- ExtraStats: Stats not on the leaderboard to show anyway, e.g. { "Power" }.
- HiddenStats: Leaderboard stats NOT to show in the HUD.
- Icons: Emoji shown next to each stat.

#### How to use
Server: Net.notify(player, "text", "success") shows a toast. Set ReplicatedStorage.GameKit attributes "Status" (text) and "Timer" (seconds) to drive the top bar.
### System: Obby checkpoints (checkpoints)

Saved stage progress, respawn on the last checkpoint, finish line rewards.

Requires: core, hud
Scripts: systems/checkpoints/Checkpoints.server.luau

#### Tags it reacts to
- "Checkpoint": part with number attribute Stage (1, 2, 3...)
- "FinishLine": end of the obby

#### Config.Checkpoints
```json
{
  "StageStat": "Stage",
  "RequireOrder": true,
  "FinishRewards": {
    "Wins": 1,
    "Coins": 50
  },
  "ResetOnFinish": true,
  "AnnounceFinish": true
}
```
- RequireOrder: Players must touch checkpoints in order (no skipping).
- FinishRewards: Stats given, e.g. { Wins = 1, Coins = 50 }. New stats appear on the leaderboard automatically.
- ResetOnFinish: Send players back to stage 1 after finishing (to replay).

#### How to use
Add checkpoints with build_world piece "checkpoint" (options: stage) or a whole course with "obby_course".

- "JumpPad": Power

#### How to use
Place pieces with build_world (moving_platform, spinner, jump_pad...). Attributes can be edited in Studio at any time.

### System: Round system (rounds)

Intermission -> round -> winners loop with timer, map rotation, rewards.

Requires: core, hud
Scripts: systems/rounds/Rounds.server.luau

#### Tags it reacts to
- "RoundSpawn": arena spawn points
- "LobbySpawn": where players return after a round

#### Config.Rounds
```json
{
  "Mode": "LastStanding",
  "MinPlayers": 1,
  "IntermissionSeconds": 15,
  "RoundSeconds": 90,
  "ResultsSeconds": 5,
  "WinnerRewards": {
    "Wins": 1,
    "Coins": 25
  },
  "ParticipationRewards": {
    "Coins": 5
  }
}
```
- Mode: "LastStanding" (last alive wins) or "Survive" (everyone alive at the end wins).
- MinPlayers: Players needed to start a round (1 = you can test alone).
- WinnerRewards: Stats given, e.g. { Wins = 1, Coins = 50 }. New stats appear on the leaderboard automatically.

#### How to use
Maps: put Models in ServerStorage.GameKit.Maps (each with RoundSpawn parts) for rotation; otherwise the Workspace arena is used.
### System: Sword combat (combat)

Ready sword tool, server-side hit detection with anti-cheat range check, kill rewards.

Requires: core, hud
Scripts: systems/combat/Combat.server.luau

#### Tags it reacts to
- "GKMelee": any Tool with this tag is a melee weapon (attributes Damage, Cooldown, Range)

#### Config.Combat
```json
{
  "GiveSword": "Always",
  "Damage": 25,
  "Cooldown": 0.6,
  "SwingWindow": 0.35,
  "Range": 6,
  "FriendlyFire": false,
  "KillRewards": {
    "Kills": 1,
    "Coins": 10
  },
  "BladeColor": "#D7DCE6",
  "HiltColor": "#6B4226"
}
```
- GiveSword: "Always", "InRound" (only during rounds) or "Never" (e.g. sold in the shop).
- KillRewards: Stats given, e.g. { Wins = 1, Coins = 50 }. New stats appear on the leaderboard automatically.

#### How to use
The sword template lives in ServerStorage.GameKit.Tools.Sword; the shop can sell it with Kind="Tool", Value="Sword".

## Guides
### How to build a great Roblox game with this MCP (read first) (`workflow`)

#### The golden path (follow in order)
1. **roblox_start_here** -- checks Studio is connected and shows what is already installed.
2. **Pick a template** that matches the idea (gamekit_catalog lists them):
   obby, tycoon, simulator, arena (PvP), survival (zombie waves), horror_escape.
   -> **create_game** { template, options }. This builds a COMPLETE playable game in one call.
   No template fits? Start from the closest one, or install systems one by one with add_system.
3. **test_game** -- plays the game automatically for ~20 s and reports errors with fixes.
   Fix every error, then test again. Repeat until it says PASS.
4. **Customise without code**:
   - numbers & texts: add_system { system, config } or edit ReplicatedStorage.GameKit.Config.<X>
   - level design: build_world (whole courses/maps or single pieces like jump_pad, coin, spinner)
   - screens: build_ui (JSON -> real UI, live stat text, buttons that open windows)
   - mood: set_environment (lighting preset + terrain)
   - advanced (find_tools + call_tool): terrain_fill_*, lighting_*, particle_create, sound_*, animation_*,
     insert_asset (Creator Store models), capture_screenshot to look at the result.
5. **Only then write code**, with write_script (it refuses broken Luau and explains fixes).
6. **check_game** before finishing: finds scripts in wrong places, syntax errors, loose parts, missing spawns.
7. Polish (see guide "design"), then publish (guide "publishing").

#### Rules that prevent 90% of bugs
- Server logic (money, damage, saving) goes in **Scripts** in ServerScriptService.
  Input, camera and UI go in **LocalScripts** (StarterPlayerScripts / StarterGui).
- Never trust the client: the client asks ("buy Sword"), the server checks and decides.
- Use **task.wait()** (never wait()), and put a task.wait() in every while-true loop.
- Parts that should not fall must be **Anchored**.
- Use GameKit's PlayerData for stats/saving instead of writing DataStore code.
- After every change: test_game. Read the errors, fix, re-test.

### What makes a Roblox game fun (checklist) (`design`)

#### Core loop (players must understand it in 10 seconds)
Action -> reward -> upgrade -> bigger action. Examples:
- Obby: jump -> checkpoint -> coins -> trails/boosts -> harder stages.
- Simulator: train -> sell -> upgrades/pets -> new zone -> rebirth.
- Tycoon: collect -> buy dropper -> more money -> bigger base.
#### Progression
- First reward in < 30 seconds. First upgrade in < 2 minutes.
- Prices grow ~1.5x per level; rewards grow too. Always show the next goal (status bar, locked zone with price).
- Rebirth/prestige gives long-term goals (simulator template has it).
#### Juice (feedback) -- makes cheap games feel premium
- Every reward shows a toast or "+N" pop-up (GameKit HUD does this automatically).
- Sounds on actions, particles on pickups, tweens on buttons (UIKit buttons animate).
- Lighting preset + color theme: set_environment { preset: "day" | "sunset" | "neon" | ... }.
#### Social & retention
- Global leaderboard (leaderboard system), daily reward with streak (daily system),
  visible cosmetics (trails, pets) so players show off.
#### Onboarding
- Welcome toast explaining the goal (Config.Core.WelcomeMessage). Signs/billboards in the world.
- The first 2 minutes must be easy. Difficulty ramps slowly (obby_course does this).
#### Mobile first (60%+ of players)
- Big buttons, no tiny text; GameKit UI is responsive. Test in Studio's device emulator.

### Luau basics for Roblox (cheat sheet) (`luau`)

```lua
local Players = game:GetService("Players")          -- always get services like this
local count = 0                                       -- local variable
count += 1                                            -- compound assignment (no ++)
local name = "Coins: " .. count                       -- string concatenation
local text = `Coins: {count}`                        -- interpolation needs BACKTICKS
if count > 5 and name ~= "" then                      -- ~= means "not equal"; and/or/not
  print("big")
elseif count == 0 then
  print("zero")
end
for i = 1, 10 do end                                  -- numeric loop
for _, player in Players:GetPlayers() do end          -- loop over a list
local t = { Coins = 10, Items = { "Sword" } }         -- table (dictionary + list)
local function add(a: number, b: number): number      -- function (types optional)
  return a + b
end
Players.PlayerAdded:Connect(function(player)          -- events: :Connect(function ... end)
  print(player.Name .. " joined")
end)
task.wait(1)          task.spawn(fn)      task.delay(2, fn)   -- NOT wait/spawn/delay
local part = Instance.new("Part")                     -- create, set props, parent LAST
part.Anchored = true
part.Size = Vector3.new(4, 1, 4)
part.Color = Color3.fromRGB(255, 0, 0)                -- 0-255 with fromRGB
part.Parent = workspace
local ok, err = pcall(function() end)                 -- catch errors (DataStores, HTTP)
```
Common mistakes: != (use ~=), // comments (use --), null (use nil), missing `end`,
"text {x}" in double quotes (not interpolated), forgetting :Connect, using . instead of :
for methods (part:Destroy(), not part.Destroy()).

### Client vs server: where each script goes (`client-server`)

| Script type | Put it in | Runs on | Use for |
|---|---|---|---|
| Script | ServerScriptService | Server | game rules, money, damage, saving, spawning |
| LocalScript | StarterPlayer > StarterPlayerScripts, StarterGui, StarterCharacterScripts | Each player's device | input, camera, UI, local effects |
| ModuleScript | ReplicatedStorage (shared) or ServerScriptService (server only) | Wherever required | reusable code/config |

- ServerStorage/ServerScriptService are invisible to clients. ReplicatedStorage is seen by both.
- A LocalScript in Workspace or ServerScriptService does NOT run. A Script in StarterPlayerScripts does NOT run.
- Communication: RemoteEvent. With GameKit:
  server: `Net.on("Buy", function(player, itemId) ... end)`  client: `Net.send("Buy", "Sword")`
  server -> client: `Net.fire(player, "Name", data)` / `Net.notify(player, "text", "success")`
- SECURITY: the server re-checks everything (price, distance, cooldown). Never accept amounts from the client.
- Players.LocalPlayer only exists in LocalScripts. On the server, get players from events.
- Characters are simulated by their owner: launching the local player (jump pads) is done client-side.

### Saving player data (PlayerData) (`data`)

Use GameKit PlayerData (installed with every system) -- it handles DataStores, retries, session locking,
autosave, shutdown saves and the leaderboard.
```lua
local PlayerData = require(game:GetService("ServerScriptService").GameKit.PlayerData)
PlayerData.defineStat({ Name = "Gems", Default = 0, Leaderstat = true })
PlayerData.onLoaded(function(player) print(player.Name, PlayerData.get(player, "Gems")) end)
PlayerData.add(player, "Gems", 5)            -- exact
PlayerData.reward(player, "Coins", 10)       -- x multipliers (passes, pets, rebirths)
if PlayerData.spend(player, "Coins", 100) then ... end
PlayerData.grant(player, "RedHat"); PlayerData.owns(player, "RedHat")
local mine = PlayerData.section(player, "Quests")  -- your own saved table
mine.Completed = (mine.Completed or 0) + 1
```
Client: `player:GetAttribute("Gems")` (every stat is mirrored as a Player attribute).
Studio: saving needs the place PUBLISHED and Game Settings > Security > "Enable Studio Access to API Services".
Without it GameKit runs in memory mode (a warning explains it) -- that is not a bug.

### Making UI without code (build_ui) (`ui`)

build_ui takes JSON. Types: frame, label, button, image, imagebutton, textbox, scroll, bar.
- position: "center" | "top" | "bottom" | "left" | "right" | "top-left" | "top-right" | "bottom-left" | "bottom-right"
- size: [w, h] -- numbers <= 1 are screen fractions, bigger numbers are pixels ([200, 50]).
- layout: "vertical" | "horizontal" | "grid" (children are arranged automatically); gap, padding.
- style: color, textColor ("#RRGGBB"), transparency, corner, stroke, gradient ["#top","#bottom"], font.
- behaviour (no code needed):
  bind: "stat:Coins" + format: "💰 {value}"   -> text follows a stat live
  bind: "state:Status"                        -> follows the round/objective status
  bar: "stat:Power/stat:Capacity"             -> progress bar (type "bar")
  showIf: "state:RoundActive" / "!state:RoundActive" / "stat:Stage>5"
  action: "toggle:WindowName" | "open:X" | "close:X" | "remote:EventName[:arg]"

### Building worlds (build_world) and Roblox space (`building`)

- Units are studs. Y is up. A character is ~5 studs tall, walks 16 studs/s, jumps ~7 studs high
  and ~12 studs far. Keep obby gaps between 3 and 9 studs.
- Every part that should not fall: Anchored = true (GameKit pieces are anchored).
- position is the CENTER of a part: a platform of height 1 at y=10 has its top at y=10.5.
- Whole worlds: obby_course, lobby, arena, maze, tycoon_plots, simulator_world, decor_scatter.
- Obstacles for obby_course: jumps, killbricks, zigzag, moving, disappearing, spinner, truss, lava_floor, falling, conveyor, jumppad, tightrope.
- Single pieces: platform, spawn, checkpoint, finish_line, kill_brick, lava_floor, damage_part, heal_pad, jump_pad, speed_pad, boost_pad, moving_platform, spinner, disappearing_platform, falling_platform, conveyor, coin, shop_stand, leaderboard, enemy_spawner, sell_pad, zone_gate, teleporter, teleport_target, key, tree, rock, lamp, crate.
- Everything goes to Workspace/GameKit/<name>; building again with the same name replaces it.
- Need something else? find_tools "terrain" / "lighting" / "asset" / "build" lists the low-level world tools
  (terrain_fill_block, lighting_set_preset, insert_asset, generate_build...).
- Each gameplay piece carries the tag + attributes its system reads, e.g. a jump_pad has tag "JumpPad"
  and attribute Power. Change attributes in Studio's Properties panel to tune it.

### Testing and fixing (test_game, check_game) (`testing`)

1. check_game -- static audit: Luau syntax, beginner mistakes, scripts in the wrong place,
   missing SpawnLocation, unanchored parts. Fast, no playtest.
2. test_game -- real playtest (~20 s): server + client errors with the script and line,
   automatic play-through (checkpoints, coins, kill parts), stats after spawn. Ends by itself.
3. For each error: open the script (get_script_source), fix it with write_script or edit_script_lines,
   re-run test_game. Do not stop while test_game reports errors.
Reading errors: "ServerScriptService.Shop:42: attempt to index nil with 'Value'"
= script Shop, line 42, something before ".Value" is nil (wrong name or not loaded yet -> WaitForChild).

### Common Roblox errors and their fix (`errors`)

- attempt to index nil with 'X' -> the thing before .X does not exist. Check the name/path, use :WaitForChild("Name") on the client.
- X is not a valid member of Y -> typo, wrong case, or not loaded yet (WaitForChild).
- Infinite yield possible on 'A:WaitForChild("B")' -> B never appears: wrong name or the server never creates it.
- attempt to call a nil value -> calling a function that does not exist (typo, or used . instead of :).
- attempt to perform arithmetic on nil -> a number variable is nil (stat not loaded / attribute missing).
- Script timeout: exhausted allowed execution time -> a loop without task.wait().
- Requested module experienced an error while loading -> the real error is in that ModuleScript (look above).
- FireServer can only be called from the client -> RemoteEvent used on the wrong side.
- DataStore / StudioAccessToApisNotAllowed -> publish + enable Studio API access (or ignore in Studio).
- HTTP 403 / Sound failed to load -> the asset is private; use public or your own assets.
- Unable to cast value to Object/Color3... -> wrong value type (Color3.fromRGB for colors, Vector3.new for sizes).

### Publishing checklist (`publishing`)

1. test_game passes with no errors; check_game shows no errors.
2. File > Publish to Roblox. Then Game Settings > Security: enable Studio Access to API Services (to test saving).
3. Create an icon (512x512) and thumbnails (1920x1080) on create.roblox.com.
4. Fill the description (what to do, controls) and the maturity questionnaire.
5. Monetization: create game passes/developer products, paste IDs in Config.Monetization.
6. Test on mobile (Studio device emulator) and with 2+ players (Test > Clients and Servers).
7. Make the experience Public. Update often; use the daily reward and events to bring players back.

### Performance tips (`performance`)

- Keep part count reasonable (< 10k for mobile). Use Models, avoid thousands of tiny parts.
- Anchor static parts. Unanchored parts cost physics every frame.
- Every while-true loop needs task.wait(); prefer events (Touched, Changed) over polling.
- Disconnect connections you no longer need; destroy temporary parts (Debris:AddItem(part, 5)).
- Do visual effects (spinning coins, tweens) on the client, game rules on the server.
- Consider Workspace.StreamingEnabled for big maps (then use WaitForChild on the client).

### GameKit module API (for custom scripts) (`gamekit-api`)

Shared (ReplicatedStorage.GameKit):

  onTag(tag, onAdded, onRemoved), onPlayer(fn), onCharacter(fn(character, player)), cooldown(seconds) -> fn(key)->bool,

  send(name, ...) [client], listen(name, handler) [client], event(name).
